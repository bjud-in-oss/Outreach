# TCK-024: One-Shot Automation (pnpm bygg) & Autonomous MCP Tool Integration

## 🎯 Intention & Mänsklig Nytta (User Utility)
* **Minskad manuell friktion:** Samlar hela utvecklingscykeln (rensning, grenskapande, planering, kodgenerering, verifiering och push) i ett enda kommando (`pnpm bygg TCK-024`).
* **Autonom nytta-kontroll:** AI-agenten utvärderar själv användarnyttan i planeringssteget utan att stoppa flödet, men eskalerar till utvecklaren i chatten endast om ett kritiskt produktbeslut direkt berör användaren och svaret genuint saknas.
* **Sömlös MCP-koppling:** Kopplar 1-Host Live Swarm-arkitekturen från TCK-023b till MCP Tool Dispatcher så att Live-agenten kan exekvera bakgrundsverktyg (t.ex. WAL-loggning och Drive-synk) utan att störa eller fördröja röstströmmen.

## 📋 Stegvis Kravspecifikation

### 1. Skript & CLI (`scripts/run-bygg.js`)
* Implementera orkestreringsskriptet som vid anrop med `pnpm bygg [TICKET_ID]`:
  1. Rensar `doc/LAST_CYCLE/*`.
  2. Hämtar senaste `origin/main` och skapar arbetsgren `feature/[ticket_id]`.
  3. Kör `pnpm planera [TICKET_ID]`.
  4. Läser `CYCLE_LOG.md` och bekräftar Steg 1a (*Intention & Mänsklig Nytta*). Om svar saknas för en direkt användarpåverkan stoppas exekveringen med en tydlig prompt i chatten.
  5. Genomför kodingreppet under `src/` och exekverar `pnpm genomfor`.
  6. Bekräftar `pnpm verify` (0 fel) och pushar arbetsgrenen till GitHub via `${GIT_PAT}`.

### 2. MCP Bridge Integration (`mcpSwarmBridge.ts`)
* Exponera `dispatchLiveHostToolCall(toolName, payload)` som tar emot verktygsanrop från 1-Host Live-agenten.
* Exekvera verktyg asynkront i bakgrunden utan att blockera Live-WebSocketens röstkablar.
* Logga alla verktygshändelser direkt i `walEngine.ts`.
