# TCK-051: Skarp Mikrofonströmning, Live-transkribering och Agentstyrd A2UI-brygga

**Måldomän:** `gemini_live_swarm` (`src/features/gemini_live_swarm/`)
**Mekanisk Acceptans:** Ett transient test bevisar (Fail-First mot körtidsankare utan mocks på domänlogik) att:
1. PCM-ljud som emitteras på `SwarmEventBus` (`'swarm.live.stream.audio'`) når den aktiva WebSocket-sessionens `sendRealtimeInput` med formatet `{ audio: { data, mimeType } }`.
2. Aktivering av röstintent (`activateIntent`) publicerar `'a2ui:render'` med `{ componentId: 'ListeningCard', dataModel: { intent: ... } }` och deaktivering publicerar `'a2ui:clear'`.
3. Verktygsanrop (`toolCall.functionCalls`) för `render_a2ui` och `clear_a2ui` från Gemini Live vidarebefordras till `SwarmEventBus` och besvaras via `sendToolResponse`.
Samtliga tester, radgränser (<250 rader i `.ts`) och FSD-arkitekturkontroller passerar med exit 0.

---

## Misstagsäkring & Systemiska Invarianter (Stoppklossar)
1. **Korrekt ljudpaket till Gemini Live SDK:**
   - I `src/features/gemini_live_swarm/session/geminiLiveSession.ts` ska `packRealtimeAudioChunk(data, mimeType)` returnera `{ audio: { data, mimeType } }` i enlighet med `@google/genai` Live API.
   - `subscribeToMicPiping` ska extrahera `audioChunkBase64` säkert och skicka ljudpaketet vidare till `this.activeSdkSession.sendRealtimeInput`.
2. **Transkribering och Live-verktyg (NON_BLOCKING):**
   - I `connectLive` ska `inputAudioTranscription: {}` och `outputAudioTranscription: {}` aktiveras samt `tools: [{ functionDeclarations: A2UI_TOOL_DECLARATIONS }]` injiceras (samtliga med `behavior: 'NON_BLOCKING'`).
   - I `handleAgentMessage` ska `message.serverContent?.outputTranscription?.text` och `inputTranscription?.text` emitteras som `'swarm.session.text_delta'` så att talat samtal syns i `TurnContainer`.
   - Vid `message.toolCall?.functionCalls` ska `render_a2ui` publicera `'a2ui:render'` på `eventBus`, `clear_a2ui` publicera `'a2ui:clear'`, och `this.sendToolResponse(...)` anropas.
3. **Automatiskt ListeningCard vid mikrofonaktivering:**
   - När `SessionIntentManager.activateIntent` i `src/features/gemini_live_swarm/session/sessionIntentAudio.ts` aktiverar en röstström ska den publicera `'a2ui:render'` med `{ componentId: 'ListeningCard', dataModel: { intent: meta.title } }`, och vid `deactivateIntent` publicera `'a2ui:clear'`.
4. **Modulär expansion (Radgräns < 250 rader):**
   - Eftersom `geminiLiveSession.ts` redan är 238 rader MÅSTE hjälpmetoder och `A2UI_TOOL_DECLARATIONS` placeras i en ny fil `src/features/gemini_live_swarm/session/liveBridgeHelper.ts` så att ingen `.ts`-fil överstiger 250 rader.
5. **Strikt FSD-isolering:**
   - Ingen import från `src/features/a2ui/` är tillåten. All kommunikation sker uteslutande via `SwarmEventBus` (`'a2ui:render'` / `'a2ui:clear'`).
   - Använd standard Vitest-assertions (`expect(...).toBeDefined()`, `expect(...).toEqual(...)`) i tester – aldrig `.toBeInTheDocument()`.

## Scenariotriad (Den relationella och systemiska avsikten)

**Scenario: ATT FÖLJA – Rösten bär fram till agenten och väcker det generativa gränssnittet**
  Givet att användaren aktiverar mikrofonen i chattfältet
  När PCM-ljudströmmen sänds över händelsebussen och agenten svarar
  Så ska ljudpaketen nå Gemini Live WebSocket utan att tappas bort, `ListeningCard` tändas automatiskt och agenten kunna styra A2UI-kort via `render_a2ui`
  Och användaren upplever ett levande, multimodalt samtal.

**Scenario: ATT VÄNDA OM – Avvisande av felaktiga ljudkuvert och blockerande verktyg**
  Givet att Gemini Live SDK kräver `{ audio: { data, mimeType } }` och `NON_BLOCKING`-verktyg
  När `GeminiLiveSession` packar ljud eller tar emot verktygsanrop
  Så ska formatet följa Live API-kontraktet strikt och verktygssvar skickas asynkront
  Så att strömningen aldrig avbryts.

**Scenario: ATT FÖRLIKAS – En ren och modulär brygga**
  Givet att källkod och tester är skapade under `src/features/gemini_live_swarm/`
  När `pnpm verify` körs
  Så ska samtliga domäntester och FSD-arkitekturkontroller passera med exit 0.
